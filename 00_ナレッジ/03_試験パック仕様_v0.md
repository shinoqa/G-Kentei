# 試験パック仕様 v0（案）

> 状態：**案**。採用・不採用はオーナー判断（意思決定ログ D-004）。
> 狙い：G検定アプリのデータ構造をほぼそのまま活かし、試験ごとの違いを「データ側」に寄せる。

## 比喩でいうと

- **エンジン＝ゲーム機本体**、**試験パック＝ソフト（カセット）**。
- 本体は1つで、ソフトを差し替えれば別の試験になる。
- G検定アプリは今「本体とソフトが溶接された状態」。まず**ソフトの形（規格）だけ**決める。

## 構造（G検定の CHAPTERS / TERM_DB を拡張）

```js
const EXAM = {
  id: "ipass",                       // localStorage の接頭辞にも使う
  name: "ITパスポート",
  source: { syllabus: "シラバス Ver.x.x", url: "https://...", checkedAt: "YYYY-MM-DD" },
  fields: [                          // 分野（足切りがある試験は分野別に集計）
    { id: "biz",  name: "…", color: "#3a7bfd" },
  ],
  tabs: ["study", "drill"],          // 任意タブ：年表(timeline) / 計算ドリル(drill) など
};

const CHAPTERS = [                   // G検定と同じ階層：章 → l1 → l2 → terms
  { id: 1, field: "biz", title: "…", color: "…", summary: "…",
    branches: [ { l1: "…", children: [ { l2: "…", terms: ["…"] } ] } ] },
];

const TERM_DB = {
  "用語": {
    term: "用語",
    category: "第1章 > …",
    definition: "定義（1〜2文）",          // 新規：3点セット①
    analogy: "中学生向けの比喩",            // 新規：3点セット②
    workRole: "業務でどんな場面に効くか",    // 新規：3点セット③（一般論のみ）
    explanation: "従来の解説文（G検定互換）",
    syllabusRef: "大分類-中分類-小分類",     // 新規：シラバスとの突き合わせ用
    questions: [
      { q: "…", opts: ["…","…","…","…"], ans: 2, exp: "…",
        type: "concept",                     // concept / calc（計算） / case（事例）
        source: "自作" }                     // 公開過去問なら「出典：令和X年度 ITパスポート試験 問N（改変あり）」
    ]
  }
};
```

## G検定との互換

- `definition / analogy / workRole / syllabusRef / type / source` は**任意項目**。無ければ従来表示。
- よって G検定アプリは今のまま動き、後から少しずつ移行できる。

## 配布方法（ビルドなし）

- 当面は「G検定の index.html を複製 → データ部分だけ差し替え」。
- 3本目の試験に着手する時点で、エンジンの共通化（1ファイル化の自動生成など）を再検討する。
  - 理由：2本では「何が試験固有か」の見極めが不十分。早すぎる共通化は手戻りのもと。
