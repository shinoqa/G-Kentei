## 2. 仕組み（どう動いているか）

```
CHAPTERS（章 → 大項目l1 → 中項目l2 → 用語terms）
      │ 描画
      ▼
マインドマップ(SVG・ドラッグ/ピンチ) ──タップ──▶ 下からシート
                                              ├ 解説（TERM_DB.explanation）
                                              └ 確認問題（TERM_DB.questions）
                                                   │ 全問正解
                                                   ▼
                                     localStorage['gkentei_progress'][用語]=true
                                                   │
                                                   ▼
                                   ホームの章カードに 習得数/総数 を表示
```

- 補助機能：全文検索、シラバス一覧、AI歴史年表タブ（期間フィルタ・頻出のみ）
- 1問でも間違えると「習得」が外れる（二値管理）

## 3. うまくいったこと（継承する）

- **地図で全体像 → 用語 → 問題** の順路。範囲の「どこにいるか」が常に見える
- 単一HTML・オフライン・スマホ前提 → 配布と更新が簡単（GitHubのWeb画面でアップロードするだけ）
- 章カードの要約文（CHAPTER_SUMMARIES）で、章を開く前に中身がつかめる

## 4. 課題（2本目で直す候補）

| 課題 | 影響 | 2本目での打ち手（案） |
|---|---|---|
| データとエンジンが1ファイルに混在 | 試験を増やすたびにコードを複製・修正 | データ部の書式（試験パック仕様）を先に決める |
| 進捗が「習得/未習得」の二値 | どこを何回間違えたか分からない | 誤答ログと復習キュー |
| 進捗キーが固定 `gkentei_progress` | GitHub Pagesで同一ドメインに複数アプリを置くと衝突しうる | 試験ごとの接頭辞 |
| 分野別の得点が見えない | 「分野ごとの足切り」がある試験に弱い | 分野別正答率の表示 |
| 年表がHTML直書き | 他試験で再利用できない | 任意タブ（年表/計算ドリル等）をデータ駆動に |
| 解説に「業務での役割」がない | 理解より暗記に寄る | 解説を3点セット化（定義・比喩・業務での役割） |
| 作業時間・誤り件数の記録がない | 2本目の改善効果を測れない | 開発ログで実測する |
